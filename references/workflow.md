# Project workflow

## Install and run

Use Node.js 22 or later with npm and an installed Google Chrome. From the skill root, install the locked dependencies and check a sample from a fresh project directory.

```text
node --version
npm ci --prefix scripts
node scripts/reproduce-example.mjs "<NEW_PROJECT_DIR>"
node scripts/accept-project.mjs "<NEW_PROJECT_DIR>"
```

Use an existing, writable parent for the new project directory. The commands were verified on Windows with Node.js 24 and Chrome. The Harbor Atlas sample requires the platform fonts listed in its DESIGN.md for exact font checks. For another Chrome channel or a host-provided module, use `STITCH_CHROME_CHANNEL`, `STITCH_YAML_MODULE` or `STITCH_PLAYWRIGHT_MODULE`. Configure the [Doop connection](doop.md) before publishing.

Replace `<PROJECT_DIR>` in the remaining commands with the actual project path.

## Inputs and outputs

| Owner | Files |
| --- | --- |
| Design source | `DESIGN.md`, source references and resource credits |
| Project configuration | `project.json`, `pages.json`, `style/card.json`, `asset/manifest.json` |
| Authored resources | `pages/*.html`, `style/icon/`, optional `style/fonts/`, `asset/raw/<category>/` |
| Generated by check | `style/card.html`, optional `style/page-typography.css`, `asset/cards/`, `asset/inventory.json`, `reports/` |
| Generated by Doop sync | `reports/doop-sync.json`, `reports/snapshots/` |
| Offline handoff | Project-built `dist/`, authored `offline.json`, ZIP and `reports/offline-acceptance.json` from the [offline command](offline.md) |

See [copyable inputs and task template](templates.md).

## Run in order

| Step | Action | Pass condition |
| --- | --- | --- |
| 1. Confirm | Select and record the source, language, theme and device or shot list. Normalize source tokens into DESIGN.md. | Every key decision has an explicit source or adaptation note. |
| 2. Build Style Card | Write the style manifest. Put local fonts in `style/fonts/` and specimen SVGs in `style/icon/`. Run the style command below. | Color, Font and Component columns render, with stable layer names and no clipping. |
| 3. Author previews | Apply the same tokens, fonts and SVGs to page HTML. Record stable frame IDs and intended behavior in the page manifest. | Actual preview dimensions, languages and links match the request. |
| 4. Declare assets | Group used materials by category in the asset manifest. Reuse existing style SVGs with `"source": "style"`. Save other originals under `asset/raw/<category>/`. | Every observed icon resolves to an ID, with asset metadata and full measurements preserved. |
| 5. Build and accept | Run validation, browser check and acceptance below. Review screenshots at normal zoom. | Commands exit 0, counts match across artifacts and screenshots are readable. |
| 6. Publish where requested | Follow [Doop delivery](doop.md). | Native results are recorded separately and repeat sync is empty. |

```text
node scripts/project-workflow.mjs style "<PROJECT_DIR>"
node scripts/validate-project.mjs "<PROJECT_DIR>"
node scripts/project-workflow.mjs check "<PROJECT_DIR>"
node scripts/accept-project.mjs "<PROJECT_DIR>"
```

The optional `project-workflow.mjs assets` command regenerates cards from existing measurements. Use the full check command when any input or preview changes.

## Authoring checks

- **Typography** — In `project.json`, use profiles keyed by device with `minWidth`, `page_title`, `section_title`, and `subsection_title`. Each role has `size` and optional `lineHeight`. Sizes must descend. Attach `data-stitch-type` to headings and `data-stitch-container="header"` to the header. Mark the link to generated page CSS with `data-stitch-page-typography` so sync can inline it. Use `mainInset` for horizontal spacing. Let a localized title container size to its wrapped text and padding. Reserve `headerHeight` for a header whose content has a verified height constraint. Use `lines` in `pages.json` checks and compare title block height across locales when the line counts differ.
- **Page manifest** — `height` is the browser viewport. Use optional `frameHeight` for a taller Doop artboard. Specify `data-route-key="target-id"` for managed routes on the same Page. Frame checks can declare `selector` with `rect`, `css`, `font`, `lang`, `text` or `count`. Use `states` entries such as `{id, click, checks}` for additional state measurements.
- **Assets** — Use `data-icon="<ASSET_ID>"` on actual icon occurrences. Maintain one shared inventory. The Style Card selection reserves those IDs, and Asset Cards render the rest. Run `check` to apply measured colors to both. A two-by-two photo sprite can declare a percentage pair in `spritePosition`.
- **Geometry** — Style Card uses 900 × 540 CSS px. Adaptive Asset Cards take their dimensions from the card index. Inspect tabs, image crops and overlays at each target viewport. The browser check uses ±1 CSS px for measured geometry and exact comparison for declared names, counts, languages and CSS values.
- **Reports** — Use `reports/layout.json` for planned coordinates, `reports/preview.json` for actual preview measurements, `reports/asset-preview.json` for card results and `asset/inventory.json` for appearances and source hashes. The acceptance command reconciles these outputs and the screenshots with the manifests. Run the browser check immediately before accepting.
